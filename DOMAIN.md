# AI-first platform

Платформа связывает сотрудников компании с проектами и агентами.

## Термины

**Сотрудник**:
Человек, связанный с компанией. В платформе сотрудника представляет учётная запись.

**Учётная запись платформы**:
Запись, которая связывает сотрудника с его GitHub-аккаунтом. Её состояние определяет возможность входа, а роль определяет полномочия сотрудника в платформе.

**Приглашение**:
Одноразовое предложение присоединиться к платформе, которое может принять указанный GitHub-аккаунт.

**Роль платформы**:
Набор полномочий сотрудника в платформе. В первой версии у активной учётной записи одна из двух ролей: «Администратор» или «Разработчик».

**Администратор**:
Сотрудник с ролью «Администратор», который управляет сотрудниками, проектами и назначениями проектов.

**Разработчик**:
Сотрудник с ролью «Разработчик», который работает с назначенными ему проектами.

**Проект**:
Единица доступа для сотрудника. Проект содержит инструкции и может включать ссылки на репозитории GitHub.

**Назначение проекта**:
Связь сотрудника с проектом, которая определяет его право на доступ к проекту и его репозиториям.
_Не используем_: участие в проекте.

**Репозиторий**:
Существующий репозиторий в организации GitHub компании, который можно включить в проект.

**Общий репозиторий**:
Репозиторий GitHub, который входит в несколько проектов.

**Инструкции проекта**:
Общий документ проекта с указаниями по подготовке рабочего окружения и проверке его готовности.

**Подключение агента**:
Персональная связь Codex с учётной записью сотрудника, через которую Codex читает доступные сотруднику сведения о проектах.

**Отзыв подключения агента**:
Закрытие доступа к платформе через конкретное подключение Codex.

**Интеграция**:
Связь платформы с внешним сервисом, через которую платформа выполняет операции от имени компании. В первой версии это связь с GitHub.

**Отключение сотрудника**:
Прекращение доступа сотрудника и его агента к новым данным через платформу и GitHub.
