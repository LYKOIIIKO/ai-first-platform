# Локальные настройки и секреты вне Git

Для локальной разработки предусмотрен .env в корне проекта. Он будет содержать локальные значения, включая порты, параметры PostgreSQL и пароль, и не должен храниться в Git. Для Git предусмотрен .env.example с названиями параметров, безопасными примерами и пояснениями. Compose-файл также будет храниться в Git и ссылаться на параметры.

Каждому сервису должны передаваться только необходимые значения. Db будет получать параметры собственной базы, api — параметры соединения с PostgreSQL, web — только публичные настройки. Обязательные значения должны проверяться при запуске с сообщением об отсутствующем параметре. Передача секретов в переменных VITE_ запрещена, поскольку такие значения доступны браузерному коду.

Локальный .env исключается из контекста сборки через .dockerignore и не включается в образы. В текущем .gitignore уже есть исключения .env и .env.* с разрешением хранить .env.example. Для технического каркаса достаточно локальных параметров PostgreSQL. Настройки и секреты GitHub и Codex определяются при проектировании подключений.

Рассмотрены отдельные файлы с подключением через Compose secrets. Они позволяют выдавать секрет конкретным сервисам, но требуют дополнительных настроек. Для личного локального окружения выбран .env. Компромисс — необходимость следить за составом передаваемых параметров и хранить локальный файл на компьютере. Решение относится к локальной разработке.

Файлы .env.example, .env и .dockerignore пока не подготовлены. Исключение секретов из сборки и работа настроек не проверены на запущенных сервисах.

Источники: [переменные Compose](https://docs.docker.com/compose/how-tos/environment-variables/variable-interpolation/), [переменные Vite](https://vite.dev/guide/env-and-mode), [Compose secrets](https://docs.docker.com/compose/how-tos/use-secrets/).
