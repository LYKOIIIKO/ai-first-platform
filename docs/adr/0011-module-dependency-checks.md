# Dependency-cruiser и ESLint для проверки импортов

Для автоматической проверки зависимостей выбраны dependency-cruiser и базовое правило ESLint no-restricted-imports. Предусматривается запуск обоих инструментов локально и при проверке pull request в GitHub. Нарушения должны завершать соответствующую проверку с ошибкой.

Dependency-cruiser будет проверять полную матрицу из [ADR-0010](0010-allowed-module-dependencies.md), обращение только к согласованным интерфейсам модулей и отсутствие циклических импортов. Импорты типов подчиняются тем же ограничениям. Разрешение путей будет настроено по конфигурации TypeScript, чтобы проверка учитывала фактические файлы зависимостей.

ESLint будет давать раннюю обратную связь при редактировании файла. В нём будут заданы простые ограничения импортов, включая обращения к внутренним файлам чужих модулей. Полная матрица зависимостей не должна дублироваться вручную в двух конфигурациях. Частичное пересечение проверок допустимо.

Рассмотрено использование только одного инструмента. Выбрана комбинация быстрой проверки отдельного файла и анализа общей схемы зависимостей. Компромисс — две конфигурации и два запуска. Проверка импортов не доказывает корректность авторизации, транзакций или произвольного SQL; эти свойства требуют отдельной проверки кода и поведения.

Решение фиксирует выбор инструментов. Установка, конфигурация и подключение проверок в GitHub выполняются после согласования структуры каталогов и точек входа модулей.
