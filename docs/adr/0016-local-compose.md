# Три сервиса Docker Compose для локальной разработки

Для основного локального режима первой версии выбран Docker Compose с сервисами web, api и db. Web будет запускать Vite и React-приложение, api — NestJS, db — PostgreSQL. Данные базы должны сохраняться между перезапусками контейнера. Изменения исходников frontend и backend должны подхватываться без ручной пересборки при каждом сохранении.

Единое описание запуска задаёт версии среды и соединения сервисов. Выбор даёт практику работы с контейнерами, их сетью и хранением данных. Компромисс — необходимость работающего Docker и настройки подхвата изменений исходников.

Рассмотрен вариант с PostgreSQL в Docker и локальным запуском приложений через pnpm. Он упрощает работу с локальными процессами, но требует отдельно поддерживать среду Node.js на компьютере. Для основного режима выбраны все три сервиса в Compose.

Проверки готовности определены в [ADR-0017](0017-local-readiness.md), локальные настройки и хранение секретов — в [ADR-0018](0018-local-settings-and-secrets.md), адреса соединений — в [ADR-0019](0019-local-networking.md). Ветки версий среды заданы в [ADR-0020](0020-runtime-versions.md), способ подхвата изменений — в [ADR-0021](0021-compose-watch.md). Точные версии образов фиксируются при подготовке конфигурации. Файлы Compose и образы приложений пока не созданы. Запуск сервисов не проверен.

Источники: [Compose Watch](https://docs.docker.com/compose/how-tos/file-watch/), [сеть Compose](https://docs.docker.com/compose/how-tos/networking/), [порядок запуска](https://docs.docker.com/compose/how-tos/startup-order/).
