# OpenAPI и типизированный HTTP-клиент

Backend описывает данные HTTP схемами Zod. Документ OpenAPI генерируется из описаний маршрутов и этих схем. Frontend генерирует типы через `openapi-typescript` и использует их с `openapi-fetch`. Схемы backend остаются на стороне API.

OpenAPI и клиентские типы хранятся в Git. Генерация работает без запущенных PostgreSQL и RabbitMQ. Проверка для pull request повторяет генерацию и завершается с ошибкой, если любой из сохранённых файлов устарел. Команды генерации и проверки описываются в корневом README.

Первый пример использует существующий `GET /health/ready` с ответами HTTP 200 и 503. Страница `/system` использует TanStack Router и TanStack Query. Она запрашивает `/api/health/ready` через прокси Vite, показывает загрузку, статус каждой зависимости и ошибку связи при недоступном API. [Проверки готовности](0017-local-readiness.md) · [Стек frontend](0003-frontend-stack.md).

Генерация позволяет обнаруживать изменения контракта при проверке типов frontend. Альтернатива — вручную поддерживать одинаковые описания на обеих сторонах. Компромисс выбранного подхода — генерацию нужно запускать при каждом изменении HTTP-контракта.

Источники. [OpenAPI в NestJS](https://docs.nestjs.com/openapi/introduction) · [Преобразование схем Zod](https://zod.dev/json-schema) · [Клиент openapi-fetch](https://openapi-ts.dev/openapi-fetch/).
