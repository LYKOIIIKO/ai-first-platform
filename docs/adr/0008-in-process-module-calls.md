# Прямые вызовы интерфейсов между модулями

Основной способ взаимодействия предметных модулей первой версии — прямые вызовы согласованных интерфейсов внутри backend-приложения. Вызывающий код получает результат или ошибку. Обращения между модулями не требуют HTTP-запросов. Операции с внешними сервисами от имени компании остаются ответственностью модуля «Интеграции».

Такой способ позволяет явно проследить порядок проверок и действий. Вызовы могут использовать async/await для ожидания базы данных или внешнего сервиса. Ожидание результата не означает выполнение отдельного фонового задания и не обеспечивает сохранение работы после остановки приложения.

Рассмотрены события как основной способ обмена. Они подходят для независимых реакций, но распределяют последовательность действий между обработчиками. Для первой версии выбран явный вызов с результатом; компромисс — зависимость вызывающего кода от интерфейса другого модуля.

Незавершённые сверки GitHub должны сохраняться и продолжаться после перезапуска согласно [согласованному порядку сверки](../design/github-access-reconciliation.md). Прямой вызов одной попытки не заменяет этот механизм. Координация нескольких модулей вынесена в прикладные сценарии: [ADR-0009](0009-application-scenarios.md). Разрешённые зависимости заданы в [ADR-0010](0010-allowed-module-dependencies.md). Реализация фонового выполнения определяется отдельно.
