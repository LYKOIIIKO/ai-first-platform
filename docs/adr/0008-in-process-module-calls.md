# Прямые вызовы и события между модулями

Для чтения актуального состояния и решений в рамках запроса предметные модули используют прямые вызовы согласованных интерфейсов внутри backend-приложения. Вызывающий код получает результат или ошибку. Обращения между модулями не требуют HTTP-запросов. Операции с внешними сервисами от имени компании остаются ответственностью модуля «Интеграции».

Такой способ позволяет явно проследить порядок проверок и действий. Вызовы могут использовать async/await для ожидания базы данных или внешнего сервиса. Ожидание результата не означает выполнение отдельного фонового задания и не обеспечивает сохранение работы после остановки приложения.

Для независимых фоновых последствий изменений используем события через RabbitMQ. Первое событие — отключение сотрудника. «Сотрудники» сохраняют изменение состояния и событие в одной транзакции PostgreSQL (transactional outbox).

RabbitMQ доставляет сохраняемые сообщения в отдельные долговечные очереди «Доступа» и «Подключений агентов». Отправитель отмечает событие как опубликованное после подтверждения брокера и проверки маршрутизации. Каждый обработчик подтверждает сообщение после сохранения результата. Повторная доставка должна быть безопасной.

Проверка актуального состояния учётной записи блокирует новые запросы сразу после отключения. Фоновое событие запускает сверку прав GitHub и отзыв подключения Codex. Смешанный подход сохраняет явный порядок решений в запросе и позволяет обработчикам выполнять последствия независимо. Компромисс — отдельный брокер и необходимость обрабатывать повторную доставку. Каркас включает RabbitMQ и проверку AMQP-соединения. Событие и обработчики появляются со сценарием отключения. [RabbitMQ: рассылка сообщений](https://www.rabbitmq.com/tutorials/tutorial-three-javascript) · [Подтверждение доставки](https://www.rabbitmq.com/docs/confirms).

Незавершённые сверки GitHub должны сохраняться и продолжаться после перезапуска согласно [согласованному порядку сверки](../design/github-access-reconciliation.md). Прямой вызов одной попытки не заменяет этот механизм. Координация нескольких модулей вынесена в прикладные сценарии: [ADR-0009](0009-application-scenarios.md). Разрешённые зависимости заданы в [ADR-0010](0010-allowed-module-dependencies.md). Устройство фоновой сверки GitHub определяется отдельно. Полученное событие запускает сверку, а нужные права рассчитываются по текущему состоянию перед каждой попыткой.
