# Проверки готовности локального окружения

Для готовности локального окружения предусмотрены отдельные проверки. Сервис db будет использовать pg_isready, чтобы подтвердить приём соединений PostgreSQL. Backend будет предоставлять /health/live для проверки ответа процесса и /health/ready для выполнения SELECT 1 через собственное соединение с настроенной базой и учётными данными. Web будет проверяться HTTP-запросом к странице Vite.

Одного pg_isready недостаточно для проверки соединения backend: состояние сервера можно получить и с неверными учётными данными. Настоящий запрос из api будет проверять адрес, учётные данные и выполнение SQL. Если база недоступна, /health/ready должен возвращать ошибку готовности. Проверка должна выполняться и после запуска приложения.

Compose должен дожидаться готовности db перед запуском api. Web должен запускаться независимо от api, чтобы интерфейс можно было открыть при недоступном backend. Общая команда проверки будет подтверждать доступность web и готовность api с базой. Отрисовка React и обращение интерфейса к backend подлежат дополнительной проверке в браузере.

GitHub не включается в общую проверку готовности. При его сбое платформа должна оставаться доступной для показа ошибок и повторных сверок. Проверка SELECT 1 подтверждает соединение с базой; корректность предметных таблиц и пользовательских сценариев проверяется отдельно при их реализации.

Рассмотрена проверка только запущенных процессов. Выбраны раздельные проверки процесса и соединения с базой, чтобы различать причины неготовности. Компромисс — дополнительные технические обработчики и команда проверки. Они относятся к окружению, а не к пользовательским функциям. Пока обработчики и команда не реализованы; готовность сервисов не проверена.

Источники: [pg_isready](https://www.postgresql.org/docs/current/app-pg-isready.html), [порядок запуска Compose](https://docs.docker.com/compose/how-tos/startup-order/).
