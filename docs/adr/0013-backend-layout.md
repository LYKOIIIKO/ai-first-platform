# Каталоги backend и точки входа предметных модулей

Целевое размещение backend — apps/api. В apps/api/src предусмотрены main.ts для запуска и app.module.ts для сборки приложения NestJS. Для кода выбраны каталоги application для прикладных сценариев, modules для предметных модулей, transport для обработки внешних запросов и infrastructure для общих технических средств.

В modules будут находиться employees, projects, access, agent-connections и integrations. Код будет группироваться по предметным модулям. Альтернатива с общими каталогами controllers, services и repositories для всего backend распределила бы код одного предметного модуля между несколькими местами.

Для каждого предметного модуля предусмотрены две открытые точки входа. Файл public.ts будет предоставлять другим модулям типы и описания доступных возможностей. Файл с именем модуля и суффиксом .module.ts, например employees.module.ts, будет подключать его при сборке приложения NestJS. Обычный межмодульный код должен использовать public.ts; файлы *.module.ts предназначены для сборки NestJS. Эти обращения подчиняются [согласованной матрице зависимостей](0010-allowed-module-dependencies.md).

Описания таблиц и внутренние реализации остаются внутри модуля-владельца. Они не становятся доступными через открытые точки входа. Выбор отдельных файлов для интерфейса и сборки делает их назначение явным; компромисс — две точки входа на модуль.

Сейчас определяется только размещение кода и открытых точек входа. Будущие операции, таблицы, классы и внутренние каталоги заранее не создаются. Детали общей технической инфраструктуры определяются по необходимости. Код приложений пока не создан.
