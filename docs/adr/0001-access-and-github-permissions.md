# Разделить правила доступа и операции с правами GitHub

При снятии назначения и изменении состава проекта действуют одни правила. Например, сотрудник сохраняет доступ к общему репозиторию, пока его даёт хотя бы один назначенный проект. Распределение этих правил между сценариями чтения, управления проектами и работы с GitHub потребовало бы поддерживать их согласованность в нескольких местах.

Модуль «Доступ» ведёт назначения, определяет требуемые права на репозитории и применяет единые правила к сотруднику и его Codex. Модуль «Интеграции» выдаёт и отзывает права в GitHub и проверяет, какие права фактически действуют. Сценарии, которые проверяют доступ или меняют права, используют решения модуля «Доступ», а для подтверждения результата внешней операции обращаются к «Интеграциям». [Предметная модель](../domain-model.md#согласованная-ответственность-модулей).

«Доступ» ведёт повторные попытки и принимает результаты для актуальной версии требуемого права. «Интеграции» выполняют одну попытку сверки для переданных аккаунта и репозитория. Такое разделение оставляет обработку изменений назначений рядом с их расчётом. [Интерфейс сверки](../design/github-access-reconciliation.md#интерфейс-модулей).
