# Модульный монолит для backend

Backend первой версии организован как одно приложение NestJS с пятью предметными модулями: «Сотрудники», «Проекты», «Доступ», «Подключения агентов» и «Интеграции». Их ответственность определена в [предметной модели](../domain-model.md). Такое устройство позволяет изучать разделение ответственности, сохраняя простой локальный запуск и отладку.

Рассмотрено выделение модулей в отдельные приложения — микросервисы. Для первой версии не выбрано независимое развёртывание предметных модулей: сетевое взаимодействие и обработка недоступности соседних приложений добавили бы отдельную сложность. Компромисс модульного монолита — совместный выпуск модулей backend.

Владение данными закреплено за модулями в одной базе PostgreSQL: [ADR-0007](0007-module-data-ownership.md). Основной способ обмена — прямые вызовы согласованных интерфейсов: [ADR-0008](0008-in-process-module-calls.md). Сквозные действия координируют прикладные сценарии: [ADR-0009](0009-application-scenarios.md). Разрешённые зависимости заданы в [ADR-0010](0010-allowed-module-dependencies.md), инструменты их проверки — в [ADR-0011](0011-module-dependency-checks.md). Выбор модульного монолита сам по себе не определяет порядок фонового выполнения сверок GitHub.
